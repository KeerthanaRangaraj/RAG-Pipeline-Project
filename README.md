# Agentic Incident Triage Platform

Turns a free-text product complaint into a structured triage decision — severity, component,
failure mode, similar historical incidents, and a grounded root-cause summary — in under
`<p95 latency>` ms.

[![ci](https://github.com/<user>/incident-triage/actions/workflows/ci.yml/badge.svg)](https://github.com/<user>/incident-triage/actions)

> **Data:** built on the public [NHTSA vehicle complaints dataset](https://www.nhtsa.gov/nhtsa-datasets-and-apis).
> No proprietary or employer data is used anywhere in this repository.

## The problem

Quality teams receive thousands of unstructured complaints. Triage is manual: read the
narrative, guess the component, search for whether it's been seen before, decide whether it's
a safety issue. It is slow, inconsistent between reviewers, and the "has this happened before"
step is the one most often skipped — which is exactly the step that catches emerging failures.

This system automates the first pass and, critically, **refuses to guess**: low-confidence
classifications and ungrounded summaries are routed to human review rather than returned.

## Architecture

```
                    ┌──────────────┐
  POST /triage ────▶│   classify   │  LLM structured output + confidence
                    └──────┬───────┘
                     conf < τ │ conf ≥ τ
                ┌────────────┘    └────────────┐
                ▼                              ▼
         ┌────────────┐               ┌────────────────┐
         │  escalate  │               │    retrieve    │  BM25 ∥ dense → RRF → rerank
         └─────┬──────┘               └────────┬───────┘
               │                               ▼
               │                      ┌────────────────┐
               │                      │   summarize    │  grounded, cited
               │                      └────────┬───────┘
               │                               ▼
               │                      ┌────────────────┐
               │◀── retries exhausted │    validate    │  citation + guardrail checks
               │                      └────────┬───────┘
               ▼                               ▼ pass
            TriageResult (needs_human_review)  TriageResult
```

Orchestrated with **LangGraph** (conditional edges + checkpointing), served by **FastAPI**,
packaged with **Docker**, deployed to **AWS EC2** via **GitHub Actions**.

## Quickstart

```bash
git clone https://github.com/<user>/incident-triage && cd incident-triage
cp .env.example .env
make up          # postgres + qdrant + api
make ingest      # download and load ~50K NHTSA complaints
make index       # build BM25 + dense indexes
```

```bash

  "complaint_id": "C-0001",
  "narrative": "While braking at low speed the pedal went to the floor with no resistance.",
  "product": "Model X 2021"
```

## Repository layout

```
src/triage/
  config.py            pydantic-settings; nothing tunable is hardcoded elsewhere
  schemas.py           the output contract — written before any model code
  data/ingest.py       NHTSA download → clean → Postgres
  retrieval/           bm25_index, dense_index, hybrid (RRF), rerank
  agents/
    state.py           LangGraph state
    graph.py           wiring only — boring on purpose
    nodes/             classify, retrieve, summarize, validate, escalate
  api/                 FastAPI app, routes, correlation-ID middleware, /metrics
  eval/                retrieval metrics + Ragas harness
data/gold/             hand-labelled evaluation sets + labelling protocol
benchmarks/            versioned raw results, committed
tests/                 pytest; nodes are unit-testable in isolation
```

## Design decisions

**Why retrieval before agents.** The hybrid pipeline was built and measured standalone first.
If Recall@10 is poor, no amount of agent orchestration fixes it — and the retrieval table
above is the evidence that each added stage actually earned its latency.

**Why a non-LLM classification baseline.** A logistic regression baseline costs an afternoon
and sometimes wins. Shipping the LLM without that comparison would be an unjustified cost.

**Why deterministic validation instead of an LLM judge in the loop.** Citation resolution and
PII checks are cheap, deterministic, and cannot hallucinate. The LLM-based evaluation (Ragas)
runs offline in CI, where latency doesn't matter.

**Why escalation is a first-class node.** A triage system that returns a confident wrong answer
is worse than one that returns nothing. Escalation rate is a reported metric, not a failure.

## Limitations

- NHTSA narratives are consumer-written; performance on structured warranty or field-service
  text is untested.
- The gold set is single-annotator, so component labels carry my own interpretation bias;
  contested cases are flagged in `data/gold/`.
- Evaluated on English only.
- Costs assume a single `<instance type>`; throughput above `<N>` rps is not characterised.
